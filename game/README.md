# My City: Inside

City builder + life simulation. Игрок строит город, а затем может зайти внутрь
любого здания и наблюдать за жизнью его жителей.

* Движок: **Godot 4.x** (проект проверен на 4.4-stable)
* Язык: **GDScript**
* Платформа: **Android**, с полноценным запуском на Windows / Linux / macOS для отладки
* Стиль: 2D изометрия (2:1), собственная векторная графика

## Запуск

Открыть папку `game/` как проект в Godot 4 и нажать F5.
Главная сцена — `res://scenes/boot/boot.tscn`.

## Self-test архитектуры

```bash
godot --headless --path game -- --selftest
```

Прогоняет 32 проверки (сервисы, изометрия, стены/двери, сериализация мира,
детекция комнат, типы комнат, целостность контента, размещение мебели, поиск
пути, формула решений ИИ, распорядок дня, приоритеты жителя, использование
мебели, жизненный цикл, навыки и прокачка, разнообразие занятий, рабочий день,
район и семьи, отношения, городские события, звук, графика, расходы дома, часы,
экономика, шина событий, сейв/лоад, планировщик симуляции) и возвращает ненулевой код выхода при любой ошибке. Годится как
проверка в CI.

Тот же отчёт виден на экране при обычном запуске игры.

## Тест ввода

```bash
godot --path game -- --demo --uitest --touchtest
godot --resolution 1600x740 --path game -- --demo --as-phone --uitest --touchtest
```

Водит по игре синтетической мышью, пальцами и клавиатурой: жмёт кнопку «Wall»
там, где она нарисована, протягивает прямоугольник стен, ставит дверь, кладёт
пол, ставит мебель, кликает по жителю, выходит по Esc; потом одним пальцем
таскает карту, двумя — зумит, а с инструментом в руке тот же жест строит, а не
двигает камеру. Проверяет только модель — что в мире действительно появилось.
10 проверок, ненулевой код выхода при провале.

Всё остальное в проекте проверяется без экрана — и потому было проверено. Ввод
проверить так нельзя, поэтому единственная часть, которой игрок реально
касается, дольше всех оставалась непроверенной. Требует дисплея (позицию курсора
знает только оконная система).

`--as-phone` — не обход проверок «это телефон?», а способ их **выполнить**:
десктопная сборка начинает отвечать на них как телефон (тач, интерфейс ×2,
мобильная раскладка), поэтому весь мобильный код можно запустить, посмотреть и
прокликать без телефона.

## Скриншот из терминала

```bash
godot --path game -- --demo --screenshot /tmp/shot.png
godot --path game -- --demo --focus 17,16 --zoom 2.0 --hour 22 --screenshot /tmp/night.png
godot --path game -- --showroom --focus 16,16 --zoom 0.95 --screenshot /tmp/all.png
```

Загружает мир, ставит камеру, сохраняет PNG и выходит. Требует настоящего
дисплея/GPU (в headless-режиме рендера нет).

| Флаг | Что делает |
|---|---|
| `--focus x,y` | центр камеры на клетке |
| `--zoom n` | зум (0.5…4.0) |
| `--hour h` | перевести часы — половина графики видна только ночью |
| `--walls n` | нажать `E` n раз (режим стен) |
| `--showroom` | выставить весь каталог мебели в обеих ориентациях |
| `--select` | открыть панель первого жителя |
| `--as-phone` | притвориться телефоном: тач, интерфейс ×2, мобильная раскладка |

`--showroom` — это способ посмотреть всю графику разом: красоту нельзя проверить
самотестом, поэтому её смотрят глазами, а самотест проверяет только размеры.

## Текущий этап

**Phase 14 — Graphics.** Плейсхолдеры заменены: 48 SVG-спрайтов (18 предметов
мебели в двух ориентациях, стены/двери/окна, полы и трава), которые генерирует
`tools/make_sprites.py` — вся изометрия описана кодом, поэтому диван физически не
может встать мимо своего пола. Жители по-прежнему рисуются кодом: рубашка, волосы
и поза берутся из модели, поэтому двух одинаковых нет, а анимация не может
разойтись с симуляцией. И главное — стены больше не загораживают то, ради чего
всё это: та стена, за которой есть комната, срезается, `E` переключает
cutaway / полные / низкие.

**Phase 13 — Polish.** Всё из Phase 1–12 плюс отдача: звуковые эффекты
(генерируются кодом, а не лежат файлами), покачивание при ходьбе, символы над
головой («z z» — спит, «$» — работает), пульсация занятой мебели, кольцо на
выбранном жителе и всплывающий текст прямо в мире — «♥ friends», «★ Cooking
level 3».

**Phase 12 — Android.** Всё из Phase 1–11 плюс мобильная адаптация: интерфейс
масштабируется по реальному dpi экрана, кнопки не мельче пальца, панели обходят
вырез и жестовую полосу, у панели жителя появилась кнопка закрытия, на телефоне
включается ограничение кадров и режим низкого энергопотребления, а радиусы подробной
симуляции уменьшены. Плюс замеренная (а не обещанная) производительность.

**Phase 11 — City Events.** Всё из Phase 1–10 плюс события города: фестиваль,
жара, эпидемия гриппа, тихие выходные, грант и счёт за ремонт. Событие ничего не
приказывает — оно меняет веса, с которыми жители и так принимают решения, поэтому
на фестивале люди сами тянутся друг к другу, а в жару — чаще в душ.

**Phase 10 — Relationships.** Всё из Phase 1–9 плюс люди: у действий появился
«социальный вес», житель охотнее садится туда, где уже кто-то есть, и тем
охотнее, чем больше этот кто-то ему нравится. Время вместе строит отношения
(−100…+100), харизма ускоряет, а игра сама сообщает: «Nina и Oscar подружились».
В панели видно, кто кому кто.

**Phase 9 — Neighbourhood.** Всё из Phase 1–8 плюс город: участки под здания
(дом, многоквартирный, магазин, офис), семьи с общей фамилией, домом и
накоплениями, заселение одной кнопкой — и правило «своя кровать»: житель
пользуется своим домом, а магазины и офисы открыты всем.

**Phase 8 — Skills & Variety.** Всё из Phase 1–7 плюс глубина: 6 навыков
(готовка, логика, спорт, музыка, живопись, харизма), которые качаются от самих
занятий и делают действия лучше, быстрее и дороже, а часть действий открывают
только с уровня. 18 предметов мебели с 20 взаимодействиями, механика «надоело»
(повтор теряет до 75% ценности и восстанавливается) и личные вкусы жителей,
поэтому два одинаковых жителя проводят вечер по-разному.

Описание архитектуры и принятых решений — в [ARCHITECTURE.md](ARCHITECTURE.md).

Управление камерой: WASD / стрелки — движение, колесо — зум, средняя кнопка —
перетаскивание, E — стены (срез / полные / низкие), G — сетка, Space — пауза,
+/− — скорость времени, F3 — отладка, M — музыка.

Строительство: 1 — выбор, 2 — стена (протяжка прямоугольника), 3 — дверь,
4 — окно, 5 — пол, 6 — тип комнаты, 7 — мебель (R — поворот), 8 — участок,
9 — заселить семью, 0 — снос, Esc — выйти из режима.

Порядок для нового дома: 8 поставить участок → 2 стены → 3 дверь → 5 пол →
7 мебель → 9 заселить семью.

На телефоне: один палец — перетаскивание карты, два пальца — зум. Когда включён
инструмент строительства, один палец рисует, а не двигает камеру.

## Язык

Игра переведена на русский. Язык переключается в настройках (кнопка показывает
текущий), а по умолчанию берётся из системы — на русском телефоне игра сразу
русская. Ключами перевода служат сами английские строки, поэтому непереведённая
строка остаётся английской, а не превращается в `UI_MENU_QUIT`.

Таблица — `assets/i18n/strings.csv`, собирается из данных:

```bash
python3 tools/make_translations.py
```

Имена и описания предметов, зданий, навыков вытаскиваются из `.tres`
автоматически, так что новый предмет сам появляется в таблице.

## Три вида на здание

`E` (или кнопка справа сверху) переключает:

1. **Сквозь стены** — стены, загораживающие комнату, срезаны. Так игра
   выглядит по умолчанию, ради этого всё и затевалось.
2. **Снаружи** — полные стены и крыши: дом выглядит домом, интерьера не видно.
3. **Без стен** — только полы, мебель и люди, то есть план этажа.

Раньше режим был один и переключался невидимой клавишей; на телефоне его вообще
нельзя было сменить.

## Главное меню и настройки

Игра открывается меню: **новый город / продолжить / настройки / выход**. Раньше
она сразу проваливалась в запущенный город — музыка играет, часы идут, а игрок,
который хотел всего лишь убавить звук, ищет клавишу на ходу.

Внутри игры то же самое открывается кнопкой **☰** справа сверху: игра встаёт на
паузу, оттуда же можно сохранить город и выйти в меню. Громкость музыки и
эффектов лежат в `user://settings.cfg` и сохраняются сразу — «применить»
нажимать не нужно, да и нечего.

## Что это за предмет

Тап по предмету без выбранного инструмента открывает панель: что это, зачем оно,
сколько стоит, что с ним можно делать, что каждое действие даёт и отнимает,
сколько длится и какой навык качает.

Всё берётся из данных самого предмета, а не из отдельного текста: если у дивана
поменяется комфорт — панель поменяется вместе с ним, и разойтись они не могут.

## Стартовый город

Новая игра начинается **в городке**, а не на пустом поле: три дома с семьями,
магазин и офис, где эти семьи работают. Причина простая — обещание игры в том,
чтобы заглянуть внутрь дома, а пустая карта просит сначала этот дом построить.

Новая игра начинается **в городке** на карте 64×64: четыре дома с семьями,
магазин, кафе, офис, спортзал, библиотека и парк — и улицы, которые всё это
соединяют. По улицам ездят машины.

Дома обставлены **по-разному** (три варианта планировки и мебели), чтобы сразу
было видно: дом — это набор решений, а не фиксированный чертёж. Всё построено
через те же реестры, которыми пользуются инструменты строительства, поэтому
любую стену, пол и предмет можно двигать, менять и сносить.

**Дороги — это материал пола.** Асфальт и тротуар лежат в том же списке, что
паркет и плитка, поэтому улицу игрок кладёт обычным инструментом «пол», машины
находят дорогу, спрашивая у земли, из чего она сделана, и ни одна другая система
не узнала о существовании дорог. Машины — декорация: они никого не возят, никому
не мешают и не сохраняются.

```bash
godot --path game -- --empty     # пустая карта, если хочется строить с нуля
```

## Отчёт о жизни города

```bash
godot --headless --fixed-fps 60 --path game -- --demo --report 5
```

Проживает N игровых дней и печатает, **как жители их провели**: куда ушли часы,
сколько разных занятий было у каждого, до чего опустились потребности, сколько
раз потребность становилась критической, что стало с деньгами, навыками и
дружбами.

Баланс был последним, что в этом проекте описывалось словом «грубый», а «грубый» —
это мнение. Отчёт превращает его в числа. Первый же прогон показал, что жители
**45% времени бодрствования стоят на месте**, а все потребности проваливаются в
ноль. Причина оказалась не в порогах, а в механике «надоело»: повтор стоил 75%
ценности, и уже использованный предмет проваливался ниже порога «делать хоть
что-нибудь». Теперь повтор стоит 45%, и это записано в самотест отдельной
проверкой.

| | было | стало |
|---|---|---|
| простой | 45.7% | 25–35% |
| сон | 20% (4.8 ч) | 20–31% (5–7.5 ч) |
| работа | 10.1% | ~16% |
| общение | 8.6% | ~12% |
| голод, минимум | 0.0 | 8–22 |
| развлечение, критично | 20 раз | 1–6 раз |

Разброс между прогонами большой: жители набираются из случайных архетипов,
поэтому «25–35%» — это честный диапазон, а не одно число.

## Производительность

```bash
godot --headless --path game -- --demo --bench 200
```

Расселяет N жителей по карте и меряет, во что обходится симуляция. Замеры на
контейнерном CPU, без рендера:

| Жителей | мс/кадр | В полной детализации |
|---|---|---|
| 40 (город) | 8.47 | 16 |
| 100 (город) | 20.88 | 41 |

Карта 64×64 и настоящий город (≈90 предметов) стоят дороже, чем пустое поле, — и
по дороге вскрылось то, о чём в `pathfinder.gd` с самого начала висел
комментарий: «на 40×40 линейного поиска минимума хватает, менять — когда город
вырастет». Город вырос: неудачный поиск пути обходил тысячи клеток, каждый раз
просматривая весь открытый список, и одно решение жителя стоило **треть
секунды**. Замена на двоичную кучу: 570 → 13.6 мс/кадр.

Рост почти плоский: от 40 до 200 жителей цикл прибавил 1.3 мс. Это результат
двух решений — планировщик раздаёт тики по кругу, а выбор действия отсекает
кандидатов до поиска пути.

## Сборка под Android

APK собирается из командной строки, без редактора. Что нужно один раз:

```bash
# 1. Шаблоны экспорта Godot 4.4 -> ~/.local/share/godot/export_templates/4.4.stable/
curl -L -o t.tpz https://github.com/godotengine/godot/releases/download/4.4-stable/Godot_v4.4-stable_export_templates.tpz
mkdir -p ~/.local/share/godot/export_templates/4.4.stable && unzip -j t.tpz -d ~/.local/share/godot/export_templates/4.4.stable

# 2. Android SDK: только build-tools (apksigner, zipalign) и platform-tools
sdkmanager "build-tools;34.0.0" "platform-tools" "platforms;android-34"

# 3. Отладочный keystore
keytool -keyalg RSA -genkeypair -alias androiddebugkey -keypass android \
        -keystore ~/debug.keystore -storepass android \
        -dname "CN=Android Debug,O=Android,C=US" -validity 9999 -deststoretype pkcs12

# 4. Пути — в настройки редактора (~/.config/godot/editor_settings-4.4.tres):
#    export/android/android_sdk_path, java_sdk_path, debug_keystore(+user, pass)
```

Дальше — одна команда, пресет `Android` уже лежит в `export_presets.cfg`:

```bash
godot --headless --path game --export-debug "Android" build/mycity-inside.apk
```

Получается подписанный debug-APK для `arm64-v8a`, minSdk 21, ~59 МБ.
Release вдвое меньше (~29 МБ) и не тянет отладочные символы:

```bash
export GODOT_ANDROID_KEYSTORE_RELEASE_PATH=~/release.keystore
export GODOT_ANDROID_KEYSTORE_RELEASE_USER=mycity
export GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD=...
godot --headless --path game --export-release "Android" build/mycity-inside.apk
```

Ключ и пароль берутся из переменных окружения, а не из пресета, — в репозитории
им не место. `armeabi-v7a` в пресете выключен: он нужен только очень старым
телефонам и удваивает размер.
Установка: `adb install -r build/mycity-inside.apk` или просто скопировать файл на
телефон и открыть.

Два условия, без которых экспорт молча падает с пустым сообщением об ошибке:
рендер должен быть **GL Compatibility** (уже стоит) и в проекте должен быть
включён `rendering/textures/vram_compression/import_etc2_astc` (тоже уже стоит).

Иконка приложения пока стандартная годотовская — `launcher_icons/*` в пресете
ждут PNG 192×192 и 432×432.

Через редактор (если удобнее мышкой):

1. Editor → Manage Export Templates → скачать шаблоны для своей версии Godot.
2. Editor Settings → Export → Android: указать путь к Android SDK и JDK 17,
   нажать Install Build Template (нужен для кастомной сборки и плагинов).
3. Project → Export → Add… → Android. Формат `.apk` для теста на устройстве,
   `.aab` для Google Play. Указать debug keystore (Godot создаёт сам) или свой
   release keystore.
4. Минимальный SDK оставить 21+, архитектуры — `arm64-v8a` (и `armeabi-v7a`,
   если нужны старые устройства).
5. Проверить, что в проекте выбран рендер **GL Compatibility** — он уже стоит
   в `project.godot`, менять не нужно.

Музыка: `assets/audio/music/morning_blocks.mp3`, играет с загрузки, M — вкл/выкл.

## Графика

Все спрайты лежат в `assets/sprites/` и собираются генератором:

```bash
python3 tools/make_sprites.py
```

Файлы закоммичены — Python нужен только чтобы их изменить, но не чтобы играть.
Правится не SVG, а описание предмета в `tools/make_sprites.py`: коробки, диски и
панели в клеточных координатах. Подробности — в
[ARCHITECTURE.md](ARCHITECTURE.md), раздел 24.
