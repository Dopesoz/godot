# Drone Factory

Мобильная игра про автоматизацию производства в духе Factorio, сделанная
специально для телефона: управление одним пальцем, пиксельная графика,
никаких конвейеров — вся логистика на дронах.

Движок: **Godot 4.4**, язык: **GDScript**, сторонних плагинов нет.

---

## Как играть

| Жест | Действие |
|---|---|
| Тап по карте | Выбрать здание, а в режиме стройки — перенести призрак в клетку |
| Повторный тап по тому же месту | Подтвердить постройку |
| Перетаскивание | Двигать карту, с инерцией после отпускания |
| Двойной тап | Приблизить на шаг |
| Двойной тап и протяжка вверх/вниз | Плавный зум **одним пальцем** |
| Щипок двумя пальцами | Привычный зум, если рук две |
| Долгое нажатие | Отменить режим строительства |

Цикл игры: бур добывает руду → дроны везут её в печь → печь плавит пластины →
дроны свозят продукцию на склад → сборщик делает детали и колбы →
лаборатория тратит колбы на исследования → открываются новые здания,
рецепты и бонусы.

Энергию дают солнечные панели; ночью питание идёт из аккумуляторов.
Здание без сети и без энергии останавливается и говорит об этом значком.

## Запуск и разработка

```bash
# запустить игру
godot --path drone_factory

# прогнать все тесты (headless, код возврата 0 — всё зелено)
godot --headless --path drone_factory --script res://tests/test_runner.gd

# выгрузить атласы графики в PNG для визуальной проверки
godot --headless --path drone_factory --script res://tests/preview_art.gd

# перегенерировать иконки приложения
godot --headless --path drone_factory --script res://tools/generate_icons.gd
```

Тестов больше трёхсот, они покрывают симуляцию, логистику, сохранения,
интерфейс и бюджеты производительности. Раннер свой, на голом GDScript:
сторонних фреймворков в проекте нет.

## Архитектура

```
src/
  core/       Constants, Events (шина сигналов), Log, Rng,
              GameWorld (владелец мира), GameSetup, GameSettings, Main
  world/      Grid (данные клеток), TileTypes, MapGenerator, TerrainRenderer
  buildings/  Building и наследники (Drill, Furnace, Assembler, SolarPanel,
              Accumulator, DronePort, Lab), Inventory, реестр и отрисовка
  systems/    Simulation (тик), PowerSystem, LogisticsSystem, ResearchSystem,
              BuildController, ResourcePool, SaveSystem, Drone
  data/       Items, Recipes, Technologies — весь баланс данными
  gfx/        Palette, PixelCanvas, TerrainArt, ObjectArt, Art, DroneRenderer
  ui/         UiTheme, UiWidgets, Hud, UiPanel и панели
  camera/     GameCamera, TouchInput
```

Несколько решений, которые определяют весь остальной код:

**Данные вместо узлов сцены.** Здания и дроны — обычные объекты, а не `Node2D`.
Тысяча узлов означала бы тысячу `_process` и обход дерева каждый кадр. Здесь
данными занимаются системы, а рисуются они пакетно: поверхность — двумя
`TileMapLayer`, здания — одним `_draw` из общего атласа, дроны — одним
`MultiMesh`.

**Фиксированный логический тик 10 Гц.** Симуляция не зависит от FPS: сто тиков
— это ровно десять секунд игрового времени на любом устройстве. Догон
отставания ограничен пятью тиками за кадр, иначе после сворачивания приложения
игра пыталась бы отсчитать тысячи тиков подряд. Дроны рисуются с интерполяцией
между тиками, поэтому полёт плавный при вдесятеро более редкой симуляции.

**Потоковая подгрузка чанков.** Мир 512×512 клеток, но в слое живут только
чанки вокруг камеры, по два чанка за кадр. Стоимость кадра не зависит от
размера мира.

**Однонаправленные зависимости.** Симуляция ничего не знает про интерфейс: она
публикует события в `Events`, а UI на них подписывается. Благодаря этому вся
игровая логика гоняется headless в тестах.

**Вся графика процедурная.** В проекте нет ни одного растрового ассета: и
тайлы, и здания, и иконки предметов рисуются кодом из общей палитры при
старте (~20 мс). APK остаётся крошечным, а смена палитры — это правка одного
файла.

## Производительность

Замеры из `tests/cases/test_performance.gd` на фабрике из 326 зданий и 48
дронов (настольная машина; телефон медленнее примерно втрое):

| Показатель | Значение |
|---|---|
| Логический тик | 2.35 мс (идёт 10 раз в секунду) |
| Кадровая часть игрового кода | 0.07 мс |
| Память | 35 МБ |
| Сохранение мира целиком | 14 мс |

Что сделано ради этого: рендерер GL Compatibility, ограничение 60 кадров,
кеш выборок реестра, индекс зданий по чанкам вместо перебора, ограничение
числа попыток раздачи заданий дронам за тик, перерисовка интерфейса и
зданий только по событиям, сжатый бинарный блоб вместо JSON-массивов в
сохранении.

## Сборка под Android

1. В редакторе один раз: **Проект → Установить шаблон сборки Android**
   (нужно для формата AAB).
2. Указать в настройках редактора путь к Android SDK и ключ подписи релиза.
   Ключи в репозитории не хранятся — это осознанное решение.
3. Экспорт:

```bash
# APK для проверки на устройстве
godot --headless --path drone_factory --export-release "Android APK (тест)"

# AAB для загрузки в Google Play
godot --headless --path drone_factory --export-release "Android AAB (Google Play)"
```

Готовность к публикации проверяется тестами (`test_export_config.gd`):
включена arm64, целевой API 34, лишних разрешений нет, иконки на месте и
нужного размера, тесты и утилиты исключены из сборки.

**Разрешения: ни одного.** Игра полностью офлайновая, ничего не собирает и
никуда не отправляет — в карточке Play это заполняется как «данные не
собираются».

Требования к устройству: Android 7.0 (API 24) и выше, OpenGL ES 3.0.

## Что можно добавить дальше

Проект намеренно остановлен на играбельном ядре. Ближайшие разумные шаги:
звук и тактильная отдача, вторая ветка исследований, статистика производства
графиками, облачные сохранения, локализация (все строки сейчас в коде
рядом с местом использования, вынести их в словарь — отдельная задача).
